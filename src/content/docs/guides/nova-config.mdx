**NOVA.md** is your personal configuration file for [Nova](/concepts/nova) — the
coordinator that executes your [Runs](/concepts/runs),
[Schedules](/concepts/schedules), [Loops](/concepts/loops) and
[Prototypes](/concepts/prototyping). It's plain Markdown: your naming
conventions, your defaults, the language you want summaries in, the things Nova
should always (or never) do.

<Aside type="tip" title="Which file do I want?">
  **NOVA.md configures the agent that executes your work.** For the assistant
  you *talk to* in the dashboard — the one that launches DevBoxes and answers
  questions in chat — you want
  [NUCLEUS.md](/guides/nucleus-config) instead. They are two different agents
  with two different files; neither one reads the other's.
</Aside>

## Where to Edit

1. Open the orchestrator at your deployment URL
2. Go to **Settings** → **App AI Assistants**
3. Find the **NOVA.md** section
4. Click **Edit NOVA.md**

Maximum length is **10,000 characters**. The character counter turns red past
the limit and saving is refused, so nothing is silently truncated — trim the
text and save again.

## Where It Applies

NOVA.md is applied to **every execution Nova performs for you**:

- Runs you start by hand, interactive or autonomous
- **Schedules firing unattended** — including at 3 a.m. with no browser open
- Loop iterations and Prototype contenders

It is stored **on the server, against your account** — not in your browser — so
a schedule keeps using it long after you close the tab, and it follows you to
another machine or another session.

**Your file, your executions.** A Schedule uses the NOVA.md of the person who
*created* it, exactly as it already uses that person's credentials and secrets.
A teammate's Runs use their own file, not yours. There is no shared or
team-wide NOVA.md.

Editing NOVA.md never changes an execution already in flight — the file is read
once when the execution is dispatched. The next one picks up your edit.

<Aside type="note">
  NOVA.md customizes the **coordinator**, not the in-DevBox
  [engine](/concepts/subagents) that writes the code. To steer the engine inside
  a repository, use that repository's own agent instructions file (`CLAUDE.md`
  and friends), which the engine reads after cloning.
</Aside>

## Example

```markdown
## Naming Convention

- DevBoxes: {repo}-{issue-number}
- Branch format: feature/{issue-number}-{slug}

## Default Preferences

- Use worker 'ovh-1' unless I say otherwise
- 8192 MB memory for every DevBox

## Custom Instructions

- Write run summaries in Spanish
- Always run the test suite before opening a PR
- Link the ticket in every PR description

## Personality

- Be concise — no preamble
- Confirm before anything destructive
```

Brace patterns like `{repo}-{issue-number}` are your literal naming templates.
Write them the way you want Nova to apply them; nothing fills them in for you.

## Improving your draft

The editor carries the sparkle (✦) — the
[prompt improver](/concepts/prompt-improver). On this field it automatically
uses the **system-prompt** rewrite rather than the task rewrite: it tidies and
organizes your preferences under your own headings, keeps your voice and your
naming templates, and never turns "be more concise" into a numbered work order.
Accept replaces the draft; Discard leaves it exactly as you typed it.

## Tips

- Write standing preferences, not one-off jobs — a job belongs in the Run's
  instruction field, where it applies to that run only.
- Every character counts against the prompt of **every** execution, so keep it
  tight. The editor shows a live token estimate.
- Your preferences never override Nova's tool contracts or safety rules — gates
  and confirmations still apply.
- Clearing the editor and saving removes the file entirely; the next execution
  carries no customization at all.
